# 使用示例

以下示例的输入均为真实可跑数据，输出由 `scripts/run_flow.py` 实跑或按 DAG 规则生成。

---

## 示例 1：标准提醒批次（脚本实跑，详见 examples/output.md）

**输入**（`examples/input.json`）：青禾轻食 6 张在途券。

**输出**（实跑，退出码 0）：4 张进提醒（当天/D-1/D-3 各按口径），1 张过期进损失统计，
1 张窗口外不发；全部挂券码。话术三条口径分别对应当天截止、D-1 紧迫、D-3 轻预告。

---

## 示例 2：同日多券冲突（频控失败处理演示）

**输入**：

```json
{
  "shop": "老王麻辣烫",
  "today": "2026-09-30",
  "coupons": [
    {"customer": "阿强", "code": "LW-A1", "face": 5, "threshold": 50, "expire": "2026-10-01", "reminded": false},
    {"customer": "阿强", "code": "LW-A2", "face": 12, "threshold": 88, "expire": "2026-10-01", "reminded": false}
  ]
}
```

**输出**（按排期规则）：同一客户同一天 ≤ 1 条 → 只提醒面额最大的 LW-A2（12 元），
LW-A1 记录「顺延至次窗口」。**不发两条**——两条提醒换两张券的核销，代价是删除率。

---

## 示例 3：重复提醒拦截（一券一提醒演示）

**输入**：

```json
{
  "shop": "老王麻辣烫",
  "today": "2026-09-30",
  "coupons": [
    {"customer": "丽丽", "code": "LW-B1", "face": 9, "threshold": 68, "expire": "2026-10-01", "reminded": true}
  ]
}
```

**输出**（实跑）：动作 =「不提醒」，话术方向 =「已提醒过，一券只提醒一次」。
上周已提醒过的券不再轰炸，客户该来自然会来。

---

## 示例 4：券码缺失中止（失败处理演示）

**输入**：

```json
{
  "shop": "烘焙坊",
  "today": "2026-09-30",
  "coupons": [
    {"customer": "阿芳", "code": "", "face": 8, "threshold": 60, "expire": "2026-10-01", "reminded": false}
  ]
}
```

**输出**：券码为归因锚，缺失即无法证明「这次到店是券带来的」——流程将该券挂起，
执行清单标注「券码待补」，不进入提醒与台账。**宁可不归因，不做糊涂账。**
