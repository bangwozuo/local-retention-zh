# 使用示例

以下示例的输入均为真实可跑数据，输出由 `scripts/run_flow.py` 实跑或按 DAG 规则生成。

---

## 示例 1：标准唤醒批次（脚本实跑，详见 examples/output.md）

**输入**（`examples/input.json`）：青禾轻食，8 名客户（含 1 活跃、1 客单价缺失）。

**输出**（实跑，退出码 0）：7 人执行清单，三桶三策略——≥90 天强召回（顶格券）、
60-89 天券触达（7 折安全线券）、30-59 天轻触达（不发券）；活跃客户剔除、客单价缺失
客户挂起不发券。券预算上限 29 元。

---

## 示例 2：全活跃客户（空桶场景）

**输入**：

```json
{
  "shop": "新开业奶茶铺",
  "毛利率": 0.65,
  "today": "2026-09-30",
  "customers": [
    {"customer": "小张", "dormant_days": 5, "客单价": 22},
    {"customer": "小李", "dormant_days": 12, "客单价": 25}
  ]
}
```

**输出**（实跑）：沉睡客户数 0，执行清单显示「（无沉睡客户）」，汇总显式标注各桶 0 人。
**不静默跳过**：结论写「当前无唤醒对象，建议把运营重心放在新客转化与首单钩子上」，
而不是硬编名单。

---

## 示例 3：数据缺失中止（失败处理演示）

**输入**（缺毛利率）：

```json
{
  "shop": "烘焙坊",
  "customers": [{"customer": "阿芳", "dormant_days": 75, "客单价": 55}]
}
```

**输出**（实跑，退出码 2）：

```text
[失败] 步骤1 数据校验未过，缺失：毛利率。请补数后重跑。
```

流程在步骤 1 中止，不进入分桶与发券——缺毛利率就无法算安全面额，宁可停下也不带病跑。

---

## 示例 4：撞期推迟（频控失败处理演示）

**输入**：某客户 dormant_days 65 天、应进券触达层，但台账显示他上周刚被会员日活动触达 2 次。

**输出**（按 DAG 规则）：该客户从本批剔除，执行清单备注「7 天内已触达 2 次（会员日），
推迟至下批」，**不改话术硬发**——频控红线优先于唤醒时效，撞期触达的投诉风险大于晚唤醒 7 天的损失。
