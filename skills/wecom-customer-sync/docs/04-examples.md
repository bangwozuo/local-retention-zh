# 使用示例

以下示例均为真实运营场景，输出按 `prompt.txt` 的双通道 SOP 与合规红线生成。

---

## 示例 1：无 API 条件的单店每周全量（通道 B 降级）

**输入**（`examples/input.json`）：企微，每周全量，通道 B（人工导出）。

**输出要点**（详见 examples/output.md）：通道 B + T+1 新鲜度；客户 1,842 条，其中「最近互动时间」缺失 214 条（11.6%）——按「不补零」规则用添加时间兜底并标记 `estimated`；沉睡分桶 312/189/96 人交给唤醒工作流；打标清单 38 条待店长确认。

---

## 示例 2：首次开通 API（通道 A 起步）

**输入**：

```json
{
  "system": "企业微信",
  "task": "每日增量：新增客户 + 删除/拉黑事件 + 来源打标",
  "channel": "A（管理员已创建自建应用）",
  "time_window": "昨日"
}
```

**输出要点**：

| 步骤 | 动作 | 失败处理 | 人工确认点 |
|---|---|---|---|
| 1 | 拉昨日新增客户 | 超时重试 1 次 → 转通道 B 补数 | 无（只读） |
| 2 | 拉删除/拉黑事件 | 缺失标注「事件缺失 N 条」 | 删除率 > 5% → 次日停群发并告警 |
| 3 | 新客打「来源渠道」标签 | 写权限未开 → 生成清单人工贴 | 清单须店主过目 |
| 4 | 产出客户事件流 JSON | 字段缺失列清单 | 无 |

权限申请顺序：先只读跑通 2 周 → 确认数据口径无误 → 单独申请写权限。凭证（corpid/secret）由店主填在平台连接器后台，全程不进对话。

## 示例 3：异常检测（删除率超阈触发熔断）

**输入**：每日增量发现昨日删除 14 人 / 触达名单 260 人（5.4%）。

**输出要点**：删除率 5.4% > 5% 预警线 → 触发**熔断规则**：次日全部群发暂停，排查三件事——① 昨日触达内容是否踩敏感词；② 是否超频（同一客户 > 1 条/天）；③ 名单是否误把活跃客户当沉睡群发。排查结论回填台账后才恢复触达。

---

## 示例 4：客户行使删除权

**输入**：客户「小林（尾号 3329）」在群里要求「把我的信息删掉」。

**输出要点**：按删除权 SOP 执行：① 3 个工作日内从导出数据、台账、分层名单中删除该客户记录；② 留痕（删除时间、操作人、范围）；③ 回复客户确认已删；④ 该客户的券码历史仅保留合规必需的财务凭证部分，不做运营用途。
