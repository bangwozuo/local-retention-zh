# 使用示例

以下示例的输入均为真实运营场景数据，输出按 `prompt.txt` 五关规则与骨架模板生成。

---

## 示例 1：新品上市 + 周末预热（详见 examples/output.md）

**输入**（`examples/input.json`）：烧烤店今早现熬酸梅汤（凌晨 4 点熬 6 小时出 50 升），配周六烧烤档预热。

**输出要点**：3 条候选（新品上市 11:00 发 / 幕后信任 17:00 发 / 天气借势 21:00 发），推荐 #1（钩子 + 两个可验证细节 + 客户证言 + 结尾提问）。自查：三条均 ≤ 140 字、零极限词、零诱导分享；#2 含素材外延伸细节（阿婆送桂花），标注「发布前需店主确认属实，否则删」。

## 示例 2：素材不足时的索要清单（防编造）

**输入**：

```json
{
  "brief": "新品上市：芝士厚蛋烧",
  "materials": "新出的，挺好吃",
  "shop_persona": "日式简餐店主理人"
}
```

**输出要点**：**不直接写**。素材无任何具体细节（时间/数量/做法/客人反应），按「不编素材」规则列出索要清单：

| 需要的细节 | 为什么需要 |
|---|---|
| 用什么芝士、几个蛋、出品一份几分钟 | 「1 个细节」关的原料 |
| 试吃的客人怎么说（原话） | 客户证言位 |
| 今天备了几份 / 上架时段 | 限量与时段位（须真实） |
| 定价多少 | 若要写价格 |

店主补齐后重跑，产出 3 条候选。

## 示例 3：限时 specials（真实限量）

**输入**：

```json
{
  "brief": "清库存：今天剩 12 份海胆饭原料，不能过夜",
  "materials": "海胆今早到货，剩 12 份，晚市卖不完就浪费；原价 68，现 45",
  "shop_persona": "认真做鱼生的高冷店主"
}
```

**输出要点**（骨架：限时 specials，17:00 发）：

> 今日海胆饭 12 份，45 元（原价 68）。
> 原因很直接：今早到的海胆，晚市卖不完就浪费了，与其扔掉不如便宜卖给你们。
> 到店说「要今天那 12 份」，先到先得，不预留。

自查：限量真实（12 份）✅｜降价理由真实（临期）✅｜暗号「要今天那 12 份」自带归因 ✅。

## 示例 4：频控拦截（today_limit 触发）

**输入**：`today_limit: 4`（今天已发 4 条，其中 2 条营销），要求再发新品 + 促销共 2 条。

**输出要点**：**砍量提醒**——今天总量将达 6 条（> 5）、营销将达 4 条（> 3），超出频控红线。给两个选项：① 新品今天必发（1 条），促销挪明天 11:00；② 若促销是当天限时的（如晚市海胆），发促销、新品挪明天。客户「刷屏疲劳」的删除是不可逆资产损耗。
