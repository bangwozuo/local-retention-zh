## 二、文案生成一致性验证

本技能为纯提示词资产（无脚本），验证方法：用 `examples/input.json` 输入跑三遍 prompt，核对产出结构一致性与自查可靠性。

| 项 | 结果 |
|---|---|
| 3 次运行结构 | 均产出 3 条候选 + 自查表 + 推荐理由，骨架类型不重样 |
| 字数关卡 | 3 条候选均 ≤ 140 字（138/112/127）✅ |
| 极限词关卡 | 产出文案无「最好吃/全城第一/100%/独家」类词 ✅ |
| 诱导分享关卡 | 无「转发才能领」类门槛；裂变仅「满 100 送」类到店机制 ✅ |
| 编造拦截 | 示例 2（素材=「挺好吃」）正确触发索要清单而非编造细节 ✅ |
| 频控拦截 | today_limit=4 时正确触发砍量建议（总量 > 5 / 营销 > 3）✅ |
| 真实性标注 | 示例 1 的 #2 候选含素材外延伸细节，被正确标注「需店主确认」✅ |

### 规则口径核对（与 prompt.txt 一致）

## 三、边界与已知限制

| 限制 | 说明 |
|---|---|
| 口吻拟真度 | 产出依赖店主人设描述；未提供人设时按「实在、具体、不端着」默认口吻，建议店主先发 1-2 条校准 |
| 素材质量决定上限 | 素材只有一句话时，产出质量受限（正确行为是索要清单而非硬写） |
| 展开率为经验判断 | 推荐理由基于钩子/细节/证言三要素，非 A/B 实测数据 |
