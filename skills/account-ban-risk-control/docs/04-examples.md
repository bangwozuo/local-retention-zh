# 使用示例

以下示例的输入均为真实运营场景数据，输出按 `prompt.txt` 内嵌规则审查得出。

---

## 示例 1：问题唤醒计划（多红线命中，拦截）

**输入**（`examples/input.json`）：

```json
{
  "action": "沉睡客户唤醒群发计划",
  "plan": "3 个注册 5 天的个人号，用群控工具按名单每天各加 60 个客户，通过后立即群发「转发本条到朋友圈，截图领取 30 元券」，每日 2 条。部分话术含「加V返现」。",
  "account_status": "新号（注册 5 天），无历史营销记录"
}
```

**输出**：整体判定**拦截**（红线 5 项 / 缓行 1 项）：

| # | 级别 | 原计划 | 命中规则 | 合规替代 |
|---|---|---|---|---|
| 1 | 🔴 | 群控工具批量加人 | 工具类·协议/群控 | 停用工具，人工用企微添加 |
| 2 | 🔴 | 注册 5 天即营销 | 新号养号 7-14 天 | 养号满 14 天再启动 |
| 3 | 🔴 | 日加 60 人/号 | 日加 ≤ 20-30 | 日加 ≤ 15 人/号 |
| 4 | 🔴 | 转发才能领券 | 诱导分享红线 | 进群直接领，分享不设门槛 |
| 5 | 🔴 | 「加V返现」 | 资金敏感词 | 「到店出示本消息享会员价」 |
| 6 | 🟡 | 日群发 2 条/客户 | 群发 ≤ 1 条/天 | 每客户每日 1 条 |

**整改后计划**（可直接执行）：企微官方群发，每客户每日 1 条（营销每周 ≤ 2），无门槛进群领券，话术去掉资金敏感词；加人改企微渠道二维码被动添加，通过率连续 2 日 < 50% 即暂停。

## 示例 2：贴线但可放行（缓行）

**输入**：

```json
{
  "action": "会员日朋友圈排期",
  "plan": "老号（注册 2 年，无降权记录），会员日当天发 6 条朋友圈：3 条生活内容 + 3 条会员日活动，不群发、不涉及转发裂变。",
  "account_status": "老号"
}
```

**输出**：整体判定**修改后放行**——营销 ≤ 3 条/天的红线未超（3 条营销正好贴线），但 6 条总量集中在一天，建议拆为会员日前 1 天 2 条预热 + 当天 4 条（营销 3 + 生活 1），避免被折叠与拉黑率上升。

## 示例 3：合规动作（放行）

**输入**：

```json
{
  "action": "到店客户企微添加",
  "plan": "收银台立牌渠道二维码，客户扫码主动添加店长企微，通过后自动打「到店客」标签并发送欢迎语 1 条。日均约 25 人扫码，通过率约 78%。",
  "account_status": "企微号，正常使用中"
}
```

**输出**：整体判定**放行**——客户主动扫码（非批量主动加人），通过率 78% 远高于 50% 停手线，欢迎语 1 条不超频控。🔵 提示：欢迎语里的领券入口改成「点击卡片直接领」，比「回复关键词领取」的完成率高约一倍。

---

## 示例 4：拟用工具审查（绝对拦截）

**输入**：

```json
{
  "action": "拟采购自动化工具",
  "plan": "供应商演示「微信个人号机器人」：自动通过好友、关键词自动回复、定时群发朋友圈，声称「模拟人工操作，不会被封」。",
  "account_status": "-"
}
```

**输出**：整体判定**拦截**——协议类 bot 通过 hook 微信协议实现，设备指纹可直接识别，「模拟人工不被封」是销售话术；封号后客户资产不可迁移、不可申诉。替代路径：企微官方 API + 会话存档（需客户同意）+ 官方群发频控内的人工操作。
