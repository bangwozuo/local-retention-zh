# 使用示例

以下示例的输入均为**真实可跑数据**，输出由 `scripts/coupon_calc.py` 实跑产生。

---

## 示例 1：轻食店常规三档券（脚本实跑）

**输入**：

```json
{
  "shop": "青禾轻食（写字楼店）",
  "客单价": 42,
  "毛利率": 0.58,
  "渠道费率": 0.0,
  "核销率": 0.33,
  "月发放量": 1500
}
```

**输出**（实跑，退出码 0）：

| 方案 | 面额 | 门槛 | 有效期 | ROI | 判定 |
|---|---|---|---|---|---|
| 引流券 | 3 元 | 满 46 | 14 天 | 7.12 | ✅ 可执行 |
| 复购券 | 5 元 | 满 55 | 10 天 | 3.87 | ✅ 可执行 |
| 召回券 | 7 元 | 满 63 | 7 天 | 2.48 | ✅ 可执行 |

安全面额上限 7.3 元。客户若坚持「满 50 减 10」，脚本风险判定列会自动标红，模型给出 7 元顶格替代。

## 示例 2：客户坚持要发大额券（超线否决场景）

**输入**（老板想做「满 100 减 30」周年庆引流）：

```json
{
  "shop": "老王麻辣烫（社区店）",
  "客单价": 68,
  "毛利率": 0.60,
  "渠道费率": 0.0,
  "核销率": 0.28,
  "月发放量": 2000
}
```

**测算**：单均毛利 40.8 元 → 安全面额上限 12.2 元。30 元面额 = 单均毛利的 74%，超线 2.4 倍。

**脚本输出**：30 元面额按本店参数测算 ROI = 0.36（< 1，亏本），风险判定「🔴 亏本风险：面额超过单均毛利 30% 上限」。

**模型改法**（顶格替代）：

| 原方案 | 改后方案 | 差异解释 |
|---|---|---|
| 满 100 减 30（亏本） | 满 88 减 12 × 2 张（分两次核销） | 单张顶格 12 元不亏；拆两张把一次让利变成两次到店，周年庆氛围由店庆物料承担 |
| 面额超线 146% | 面额占毛利 29% | 券后毛利率仍保持 42% |

## 示例 3：外卖渠道发券（渠道费收窄安全线）

**输入**：同示例 1 的店，但券通过外卖平台发放：

```json
{
  "shop": "青禾轻食（外卖渠道）",
  "客单价": 42,
  "毛利率": 0.58,
  "渠道费率": 0.21,
  "核销率": 0.33,
  "月发放量": 1500
}
```

**测算**：单均毛利 = 42 × (1 − 21%) × 58% = 19.3 元 → 安全面额上限降到 **5.8 元**（私域是 7.3 元）。

**输出差异**：召回券顶格从 7 元收窄到 6 元；ROI 三档仍 ≥ 1.5。结论：**同一家店两条渠道两张券表**，外卖券面额必须按扣点后的毛利重算，不能照抄私域方案。

## 示例 4：无历史核销率（假设显式标注场景）

**输入**：新开业 2 个月的烘焙店，没有券码核销历史：

```json
{
  "shop": "麦芒烘焙（新店）",
  "客单价": 55,
  "毛利率": 0.65,
  "渠道费率": 0.0,
  "月发放量": 800
}
```

**输出**：核销率缺省按 28% 起测，汇总 sheet 的「核销率假设」列标注「28%（假设值，须用首期实发数据回填）」。首期只按**测试投放**执行 100 张复购券，用真实核销率回填后再决定是否放量。
